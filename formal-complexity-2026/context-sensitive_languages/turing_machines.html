Turing machines

Turing machines,1 like finite-state automata and pushdown automata, are a kind of abstract computing device which we can use to recognize languages. They are more powerful, however; in fact, they provide one of the foundational definitions of an effective procedure (along with the λ-calculus and Gödel’s definition of partial recursive function). Any function that can be computed at all—i.e., any procedure which can be carried out, given some input, by following a formal set of instructions—can be computed/carried out by a Turing machine.2

Definition

Following Partee et al. (1990), a Turing machine can be defined as in (1).

  1. A Turing machine is a tuple \(⟨K, Σ, q_{0}, δ⟩\), where:
  • \(K\) is a finite set of states;
  • \(Σ\) is a finite set—the alphabet—containing the symbol \(\#\) as an element;
  • \(q_{0} ∈ K\) is the initial state;
  • and \(δ\) is a partial function from \(K × Σ\) to \(K × (Σ ∪ \{\mathtt{R}, \mathtt{L}\})\).

That is, \(δ\) is allowed to be defined on only some pairs of states and alphabet symbols. It may be defined on all possible pairs of states and alphabet symbols (like a DFA is), but it doesn’t have to be.

We regard a Turing machine as operating on an infinite tape—an infinitely long string of symbols of the alphabet. In general, this tape starts out with a string of symbols from some subset of \(Σ\) (which we can call \(Σ_{1}\)), with an infinite string of \(\#\)’s on either side. This starting string represents the input to the Turing machine. For example, if the input is the string \(ab\), we represent it as the infinite string \[\ldots\#\# ab\#\#\dots\] We feed this input to the Turing machine by assuming the machine “begins” in its initial state \(q_{0}\), with the first letter of the string, \(a\), in focus. We can represent this situation as \[\ldots\#\# a^{q_{0}}b\#\#\dots\] where we write the current state as a superscript on the focused symbol in the input string.

The function \(δ\) tells us how to map input states and symbols to pairs of output states and either (a) a new symbol, or (b) an instruction to move left (\(\mathtt{L}\)) or right (\(\mathtt{R}\)). Thus if the definition of \(δ\) includes the specification \(δ(q_{0}, a) = ⟨q_{1}, \mathtt{R}⟩\)—or written a little more perspicuously, \[⟨q_{0}, a⟩ → ⟨q_{1}, \mathtt{R}⟩\] then the Turing machine produces the following situation from the one above: \[\ldots\#\# ab^{q_{1}}\#\#\dots\] If it instead had the specification \[⟨q_{0}, a⟩ → ⟨q_{1}, b⟩\] which says not to move right, but to overwrite the current symbol with \(b\), then it would instead produce the following situation: \[\ldots\#\# b^{q_{1}}b\#\#\dots\]

Accepting and deciding

Given an input string, one of two things might happen. First, the Turing machine might halt. This happens when the Turing machine is focused on a symbol \(x\) and in a state \(q\) such that \(δ(q, x)\) is undefined—i.e., it doesn’t map \(⟨q, x⟩\) to anything. Second, the Turing machine might never halt. This happens if every future state-symbol pair it encounters is mapped to something by \(δ\). For instance, if \(δ\) is a total function, then the Turing machine never halts on any string.

When a Turing machine halts on some input string, we say that it accepts that string. When it fails to halt on some input string, we say that it doesn’t accept that string. By extension, if a Turing machine halts on every string in some language \(L\) and no string not in \(L\), we say that the Turing machine accepts \(L\).

Meanwhile, we can also construct a notion of deciding, rather than just mere accepting. First, we specify a subset of states \(F ⊆ K\), which we call final states, and we consider a subset \(Σ_{1} ⊆ Σ\) of possible symbols of the input alphabet (where \(\# ∉ Σ_{1}\)). If, for some language \(L ⊆ Σ_{1}^{*}\), a Turing machine halts on every \(s ∈ L\) in a final state \(q_{\textit{f}} ∈ F\) and in a non-final state \(q_{\textit{nf}} ∈ K - F\) on every \(s′ ∈ Σ_{1}^{*} - L\), we say that the Turing machine decides \(L\). The idea is that strings on which the machine halts in a final state are in the language, while strings on which the machine halts in a non-final state are not in the language.

Example: \(a^{n}b^{n}\)

Let’s construct a Turing machine that accepts the language \[\{a^{n}b^{n} ∣ n ≥ 0\}\] (It will then just be a hop and a skip to turn that machine into one that decides the language.)

The alphabet for this machine will be \(Σ = \{a, b, A, B, \#\}\), and possible input strings will be in the set \(\{a, b\}^{*}\).

\(\begin{align*} ⟨q_{0}, a⟩ &→ ⟨q_{A}, A⟩ \\ ⟨q_{0}, b⟩ &→ ⟨q_{\textit{reject}}, b⟩ \\ ⟨q_{0}, B⟩ &→ ⟨q_{\textit{check}}, \mathtt{R}⟩ \\[2mm] ⟨q_{A}, A⟩ &→ ⟨q_{A}, \mathtt{R}⟩ \\ ⟨q_{A}, a⟩ &→ ⟨q_{A}, \mathtt{R}⟩ \\ ⟨q_{A}, B⟩ &→ ⟨q_{A}, \mathtt{R}⟩ \\ ⟨q_{A}, b⟩ &→ ⟨q_{B}, B⟩ \\ ⟨q_{A}, \#⟩ &→ ⟨q_{\textit{reject}}, \#⟩ \\[2mm] ⟨q_{B}, B⟩ &→ ⟨q_{B}, \mathtt{L}⟩ \\ ⟨q_{B}, a⟩ &→ ⟨q_{B}, \mathtt{L}⟩ \\ ⟨q_{B}, A⟩ &→ ⟨q_{0}, \mathtt{R}⟩ \\[2mm] ⟨q_{\textit{check}}, B⟩ &→ ⟨q_{\textit{check}}, \mathtt{R}⟩ \\ ⟨q_{\textit{check}}, a⟩ &→ ⟨q_{\textit{reject}}, a⟩ \\ ⟨q_{\textit{check}}, b⟩ &→ ⟨q_{\textit{reject}}, b⟩ \\[2mm] ⟨q_{\textit{reject}}, a⟩ &→ ⟨q_{\textit{reject}}, \mathtt{R}⟩ \\ ⟨q_{\textit{reject}}, b⟩ &→ ⟨q_{\textit{reject}}, \mathtt{R}⟩ \\ ⟨q_{\textit{reject}}, A⟩ &→ ⟨q_{\textit{reject}}, \mathtt{R}⟩ \\ ⟨q_{\textit{reject}}, B⟩ &→ ⟨q_{\textit{reject}}, \mathtt{R}⟩ \\ ⟨q_{\textit{reject}}, \#⟩ &→ ⟨q_{\textit{reject}}, \mathtt{R}⟩ \end{align*}\)

This Turing machine behaves as follows. Given a string \(aa\ldots bb\ldots\), it replaces the first \(a\) with an \(A\), enters the state \(q_{A}\), and then heads East in search of \(b\). When it finds \(b\), it replaces it with a \(B\), and then heads back West in search of an \(A\) (at which point it goes back to \(q_{0}\)). So on, until every \(a\) is replaced with an \(A\) and every \(b\) is replaced with a \(B\). If the numbers of \(a\)’s and \(b\)’s don’t match in the input string, the machine won’t halt. Similarly, for strings such as \(abab\)—in which an \(a\) occurs after a \(b\)—as well as strings that start with \(b\)’s.

We can easily modify this Turing machine to make it one that decides \(\{a^{n}b^{n} ∣ n ≥ 0\}\), rather than just accepts it. Specifically, we can just get rid of all the transitions from the state \(q_{\textit{reject}}\) so that the machine always halts, designate \(q_{\textit{check}}\) as the sole final state, and add the transition

\(\begin{align*} ⟨q_{0}, \#⟩ &→ ⟨q_{\textit{check}}, \#⟩ \end{align*}\)

so that the machine halts in its final state on the empty string. Making these changes yields the following definition of \(δ\):

\(\begin{align*} ⟨q_{0}, a⟩ &→ ⟨q_{A}, A⟩ \\ ⟨q_{0}, b⟩ &→ ⟨q_{\textit{reject}}, b⟩ \\ ⟨q_{0}, B⟩ &→ ⟨q_{\textit{check}}, \mathtt{R}⟩ \\ ⟨q_{0}, \#⟩ &→ ⟨q_{\textit{check}}, \#⟩\\[2mm] ⟨q_{A}, A⟩ &→ ⟨q_{A}, \mathtt{R}⟩ \\ ⟨q_{A}, a⟩ &→ ⟨q_{A}, \mathtt{R}⟩ \\ ⟨q_{A}, B⟩ &→ ⟨q_{A}, \mathtt{R}⟩ \\ ⟨q_{A}, b⟩ &→ ⟨q_{B}, B⟩ \\ ⟨q_{A}, \#⟩ &→ ⟨q_{\textit{reject}}, \#⟩ \\[2mm] ⟨q_{B}, B⟩ &→ ⟨q_{B}, \mathtt{L}⟩ \\ ⟨q_{B}, a⟩ &→ ⟨q_{B}, \mathtt{L}⟩ \\ ⟨q_{B}, A⟩ &→ ⟨q_{0}, \mathtt{R}⟩ \\[2mm] ⟨q_{\textit{check}}, B⟩ &→ ⟨q_{\textit{check}}, \mathtt{R}⟩ \\ ⟨q_{\textit{check}}, a⟩ &→ ⟨q_{\textit{reject}}, a⟩ \\ ⟨q_{\textit{check}}, b⟩ &→ ⟨q_{\textit{reject}}, b⟩ \end{align*}\)

## Accepting and deciding

Given an input string, one of two things might happen.
First, the Turing machine might halt.
This happens when the Turing machine is focused on a symbol $x$ and in a state $q$ such that $δ(q, x)$ is undefined---i.e., it doesn't map $⟨q, x⟩$ to anything.
Second, the Turing machine might *never* halt.
This happens if every future state-symbol pair it encounters is mapped to something by $δ$.
For instance, if $δ$ is a total function, then the Turing machine never halts on *any* string.

When a Turing machine halts on some input string, we say that it *accepts* that string.
When it fails to halt on some input string, we say that it doesn't accept that string.
By extension, if a Turing machine halts on every string in some language $L$ and no string not in $L$, we say that the Turing machine accepts $L$.

Meanwhile, we can also construct a notion of *deciding*, rather than just mere accepting.
First, we specify a subset of states $F ⊆ K$, which we call *final states*, and we consider a subset $Σ_{1} ⊆ Σ$ of possible symbols of the input alphabet (where $\# ∉ Σ_{1}$).
If, for some language $L ⊆ Σ_{1}^{*}$, a Turing machine halts on every $s ∈ L$ in a final state $q_{\textit{f}} ∈ F$ and in a non-final state $q_{\textit{nf}} ∈ K - F$ on every $s′ ∈ Σ_{1}^{*} - L$, we say that the Turing machine *decides* $L$.
The idea is that strings on which the machine halts in a final state are *in* the language, while strings on which the machine halts in a non-final state are *not in* the language.

## Example: $a^{n}b^{n}$

Let's construct a Turing machine that accepts the language
$$\{a^{n}b^{n} ∣ n ≥ 0\}$$
(It will then just be a hop and a skip to turn that machine into one that decides the language.)

The alphabet for this machine will be $Σ = \{a, b, A, B, \#\}$, and possible input strings will be in the set $\{a, b\}^{*}$.

$\begin{align*}
⟨q_{0}, a⟩ &→ ⟨q_{A}, A⟩ \\
⟨q_{0}, b⟩ &→ ⟨q_{\textit{reject}}, b⟩ \\
⟨q_{0}, B⟩ &→ ⟨q_{\textit{check}}, \mathtt{R}⟩ \\[2mm]
⟨q_{A}, A⟩ &→ ⟨q_{A}, \mathtt{R}⟩ \\
⟨q_{A}, a⟩ &→ ⟨q_{A}, \mathtt{R}⟩ \\
⟨q_{A}, B⟩ &→ ⟨q_{A}, \mathtt{R}⟩ \\
⟨q_{A}, b⟩ &→ ⟨q_{B}, B⟩ \\
⟨q_{A}, \#⟩ &→ ⟨q_{\textit{reject}}, \#⟩ \\[2mm]
⟨q_{B}, B⟩ &→ ⟨q_{B}, \mathtt{L}⟩ \\
⟨q_{B}, a⟩ &→ ⟨q_{B}, \mathtt{L}⟩ \\
⟨q_{B}, A⟩ &→ ⟨q_{0}, \mathtt{R}⟩ \\[2mm]
⟨q_{\textit{check}}, B⟩ &→ ⟨q_{\textit{check}}, \mathtt{R}⟩ \\
⟨q_{\textit{check}}, a⟩ &→ ⟨q_{\textit{reject}}, a⟩ \\
⟨q_{\textit{check}}, b⟩ &→ ⟨q_{\textit{reject}}, b⟩ \\[2mm]
⟨q_{\textit{reject}}, a⟩ &→ ⟨q_{\textit{reject}}, \mathtt{R}⟩ \\
⟨q_{\textit{reject}}, b⟩ &→ ⟨q_{\textit{reject}}, \mathtt{R}⟩ \\
⟨q_{\textit{reject}}, A⟩ &→ ⟨q_{\textit{reject}}, \mathtt{R}⟩ \\
⟨q_{\textit{reject}}, B⟩ &→ ⟨q_{\textit{reject}}, \mathtt{R}⟩ \\
⟨q_{\textit{reject}}, \#⟩ &→ ⟨q_{\textit{reject}}, \mathtt{R}⟩
\end{align*}$

This Turing machine behaves as follows.
Given a string $aa\ldots bb\ldots$, it replaces the first $a$ with an $A$, enters the state $q_{A}$, and then heads East in search of $b$.
When it finds $b$, it replaces it with a $B$, and then heads back West in search of an $A$ (at which point it goes back to $q_{0}$).
So on, until every $a$ is replaced with an $A$ and every $b$ is replaced with a $B$.
If the numbers of $a$'s and $b$'s don't match in the input string, the machine won't halt.
Similarly, for strings such as $abab$---in which an $a$ occurs after a $b$---as well as strings that start with $b$'s.

We can easily modify this Turing machine to make it one that *decides* $\{a^{n}b^{n} ∣ n ≥ 0\}$, rather than just accepts it.
Specifically, we can just get rid of all the transitions from the state $q_{\textit{reject}}$ so that the machine always halts, designate $q_{\textit{check}}$ as the sole final state, and add the transition

$\begin{align*}
⟨q_{0}, \#⟩ &→ ⟨q_{\textit{check}}, \#⟩
\end{align*}$

so that the machine halts in its final state on the empty string.
Making these changes yields the following definition of $δ$:

$\begin{align*}
⟨q_{0}, a⟩ &→ ⟨q_{A}, A⟩ \\
⟨q_{0}, b⟩ &→ ⟨q_{\textit{reject}}, b⟩ \\
⟨q_{0}, B⟩ &→ ⟨q_{\textit{check}}, \mathtt{R}⟩ \\
⟨q_{0}, \#⟩ &→ ⟨q_{\textit{check}}, \#⟩\\[2mm]
⟨q_{A}, A⟩ &→ ⟨q_{A}, \mathtt{R}⟩ \\
⟨q_{A}, a⟩ &→ ⟨q_{A}, \mathtt{R}⟩ \\
⟨q_{A}, B⟩ &→ ⟨q_{A}, \mathtt{R}⟩ \\
⟨q_{A}, b⟩ &→ ⟨q_{B}, B⟩ \\
⟨q_{A}, \#⟩ &→ ⟨q_{\textit{reject}}, \#⟩ \\[2mm]
⟨q_{B}, B⟩ &→ ⟨q_{B}, \mathtt{L}⟩ \\
⟨q_{B}, a⟩ &→ ⟨q_{B}, \mathtt{L}⟩ \\
⟨q_{B}, A⟩ &→ ⟨q_{0}, \mathtt{R}⟩ \\[2mm]
⟨q_{\textit{check}}, B⟩ &→ ⟨q_{\textit{check}}, \mathtt{R}⟩ \\
⟨q_{\textit{check}}, a⟩ &→ ⟨q_{\textit{reject}}, a⟩ \\
⟨q_{\textit{check}}, b⟩ &→ ⟨q_{\textit{reject}}, b⟩
\end{align*}$
