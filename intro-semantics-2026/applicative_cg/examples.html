Determining syntactic categories and semantic types from English descriptions

\[ \newcommand{\expr}[3]{\begin{array}{c} #1 \\ \bbox[lightblue,5px]{#2} \end{array} ⊢ #3} \newcommand{\ct}[1]{\bbox[font-size: 0.8em]{\mathsf{#1}}} \newcommand{\abbr}[1]{\bbox[transform: scale(0.95)]{\mathtt{#1}}} \def\true{\ct{T}} \def\false{\ct{F}} \]

The assignment asks you to determine syntactic categories and their corresponding semantic types based on English descriptions of how expressions having those categories behave (and the general procedure we have for converting syntactic categories into their corresponding semantic types). Let’s look at a few examples of this.

First example

This expression takes a sentence to its right, and then a sentence to its left, to form a sentence.

Determining the syntactic category

Because the expression first takes a sentence to its right, we know that its syntactic category is going to look as follows: \[(\ldots / s)\] That is, we know that this category’s main operator is a right slash (\(/\)) because the first thing the expression does is take something to its right; and we know that the category appearing to the right of this right slash is \(s\) because the thing the expression takes to its right is a sentence. In tree notation, the category would look as follows (where the ellipsis (‘\(\ldots\)’) represents the rest of the category, which is still TBD):

  (/)
  / \
...  s

After the expression takes the sentence to its right, it takes another sentence to its left. Knowing this, we can begin to say something about what’s missing (the ‘\(\ldots\)’). In particular, what we want to substitute in for the missing part is a syntactic category for an expression that takes a sentence to its left. In general, such a category looks as follows: \[(s\backslash \ldots)\] Or in tree notation:

  (\)
  / \
 s  ...

If we want, we can now substitute this result in for what was missing in the syntactic category above. If we do this, we get the following (partial) category: \[((s\backslash \ldots)/s)\] Or in tree notation:

   (/)
   / \
 (\)  s
 / \
s  ...

Finally, when the expression has taken a sentence to its right and then a sentence to its left, it produces a sentence. Thus we know how to finish the tree: just stick an \(s\) in for the last missing part: \[((s\backslash s)/s)\] Or in tree notation:

   (/)
   / \
 (\)  s
 / \
s   s

Determining the semantic type

Now that we have the syntactic category, we can use it to determine its corresponding semantic type. One way to do this is by starting at the root of the syntactic category represented in tree notation and working our way down. Because the root of this tree is a right slash (\(/\)), and because its right child is an \(s\), we know that the root of the semantic type tree is going to be an arrow (\(→\)) and that its left child is going to be a \(t\) (recall that the semantic type of \(s\) is \(t\), and that for right slashes, the arrow “points the other way”):

   ─>
  / \
 t  ...

Meanwhile, the right child of this semantic type tree will be the semantic type corresponding to the left child of the (\(/\)) in the syntactic category tree. By looking at the syntactic category tree above, we can see the left child of the root (\(/\)) is the following tree:

 (\)
 / \
s   s

Thus we can get the relevant semantic type by converting this left slash (\(\backslash\)) into an arrow (\(→\)) whose left child corresponds to the syntactic category on the left, and whose right child corresponds to the syntactic category on the right. Both of these syntactic categories are \(s\), which means that the two children in the semantic type will both be \(t\):

   ─>
  / \
 t   t

With the semantic type corresponding to \((s\backslash s)\) in hand, we can show the complete semantic type corresponding to \(((s\backslash s)/s)\) by filling in what was missing above:

  ─>
 / \
t   ─>
   / \
  t   t

We now have the full semantic type, in tree notation. If we want to represent this semantic type using the more typical parentheses notation, we would write it as: \[(t → (t → t))\]

What category and type are these?

In fact, this syntactic category—\(((s\backslash s)/s)\)—and its corresponding semantic type—\((t → (t → t))\)—can be seen to be useful in our system for describing English. Specifically, it is useful to view \(((s\backslash s)/s)\) as the syntactic category of sentence-level coordinators, like and, and thus \((t → (t → t))\) as its semantic type. Note that sentence-coordinator and appears to behave as described.

  1. Jo jumps and Bo runs.

In (1), we can view and as first combining with the sentence Bo runs (“This expression takes a sentence to its right…”) to form the string and Bo runs. This string then combines with Jo jumps (“…and then a sentence to its left…”) to form the string Jo jumps and Bo runs, delivering an \(s\).

If we view sentence-coordinator and as having syntactic category \(((s\backslash s)/s)\), then we also have to regard it as having semantic type \((t → (t → t))\). This is the semantic type of functions that first take a truth value argument, and then another truth value argument, and return a truth value. One such function, which we can call \(f_{\textit{and}}\), behaves as follows: \[\begin{align*} f_{\textit{and}}(a)(b) &= \true \text{ if } a = \true \text{ and } b = \true \\ &= \false \text{ otherwise} \end{align*}\] Here, \(a\) and \(b\) represent two possible truth values—they could be either \(\true\) or \(\false\)—which we can feed, in turn, to \(f_{\textit{and}}\) as its two arguments. When \(f_{\textit{and}}\) is applied to \(a\), it gives back the result \(f_{\textit{and}}(a)\)—this is a new function of type \((t → t)\). When it is then applied to \(b\) (yielding \(f_{\textit{and}}(a)(b)\)), it returns a truth value—something of type \(t\). The truth value it returns is \(\true\) if and only if its two arguments (\(a\) and \(b\)) were \(\true\); if either of them was \(\false\), \(f_{\textit{and}}(a)(b)\) returns \(\false\).

And \(f_{\textit{and}}\) seems to be a good meaning for the English word and. It makes the whole sentence that it forms true if and only if the two sentences that it coordinates are true. For example, it allows us to ensure that (1) is evaluated to be true if and only if both the sentences Jo jumps and Bo runs are evaluated to be true; if either of these sentences comes out false, then so does (1) as a whole. The following derivation, which assumes meanings for runs and jumps that follow the model in An English model and example, shows this: \[\begin{prooftree} \AxiomC{$⟨\textit{Jo}, \ct{j}⟩ ⊢ np$} \AxiomC{$⟨\textit{jumps}, \{\ct{j}\}_{CF}⟩ ⊢ (np\backslash s)$} \RightLabel{$\backslash$}\BinaryInfC{$⟨\textit{Jo jumps}, \{\ct{j}\}_{CF}(\ct{j})⟩ ⊢ s$} \AxiomC{$⟨\textit{and}, f_{\textit{and}}⟩ ⊢ ((s\backslash s)/s)$} \AxiomC{$⟨\textit{Bo}, \ct{b}⟩ ⊢ np$} \AxiomC{$⟨\textit{runs}, \{\ct{j}, \ct{b}\}_{CF}⟩ ⊢ (np\backslash s)$} \RightLabel{$\backslash$}\BinaryInfC{$⟨\textit{Bo runs}, \{\ct{j}, \ct{b}\}_{CF}(\ct{b})⟩ ⊢ s$} \RightLabel{$/$}\BinaryInfC{$⟨\textit{and Bo runs}, f_{\textit{and}}(\{\ct{j}, \ct{b}\}_{CF}(\ct{b}))⟩ ⊢ (s\backslash s)$} \RightLabel{$\backslash$}\BinaryInfC{$⟨\textit{Jo jumps and Bo runs}, f_{\textit{and}}(\{\ct{j}, \ct{b}\}_{CF}(\ct{b}))(\{\ct{j}\}_{CF}(\ct{j}))⟩ ⊢ s$} \end{prooftree}\]

Evaluating the result

The interpretation that results from this derivation is the following: \[f_{\textit{and}}(\{\ct{j}, \ct{b}\}_{CF}(\ct{b}))(\{\ct{j}\}_{CF}(\ct{j}))\] Note that this result consists of the function \(f_{\textit{and}}\) applied to two arguments. The first argument is \[\{\ct{j}, \ct{b}\}_{CF}(\ct{b})\] and the second argument is \[\{\ct{j}\}_{CF}(\ct{j})\] Since \(\{\ct{j}, \ct{b}\}_{CF}(\ct{b}) = \true\) and \(\{\ct{j}\}_{CF}(\ct{j}) = \true\) (both are true), we can evaluate the whole result to the following: \[f_{\textit{and}}(\true)(\true)\] If we consult the definition of \(f_{\textit{and}}\) that used arbitrary truth values \(a\) and \(b\), we can see that our \(a\) and \(b\) here are both \(\true\). Thus \(f_{\textit{and}}(\true)(\true) = \true\), which means that the interpretation of (1) is \(\true\).

Second example

This expression combines with an expression \(X\) to its left, where \(X\) is something that takes a sentence to its right to form a verb phrase, and together with \(X\), it forms a sentence.

Determining the syntactic category

Let’s start out by not immediately worrying what the category of \(X\) is. Instead, let’s just assume that it has some category and figure out what should surround the category, given the description above. The description says that—whatever \(X\) is—the relevant expression combines with \(X\) to its left and forms a sentence. Thus the syntactic category of this expression will look as follows: \[(\ldots \backslash s)\] where the ‘\(\ldots\)’ is where the category of \(X\) should go. In tree notation, this category can be represented:

  (\)
  / \
...  s

Let’s now figure out what category \(X\) has. The description says that \(X\) is something that takes a sentence to its right to form a verb phrase. Recall that a verb phrase in our current system has the category \((np\backslash s)\). So, something that takes a sentence to its right to form a verb phrase has the following category: \[((np\backslash s)/s)\] Or in tree notation:

   (/)
   / \
 (\)  s
 / \
np  s

This is the syntactic category of \(X\)—what was missing in the full syntactic category that we want to determine. If we substitute the tree representing the syntactic category of \(X\) for the missing part in the tree representing the full syntactic category, we end up with the following result:

     (\)
     / \
   (/)  s
   / \
 (\)  s
 / \
np  s

Or in regular parentheses notation: \[(((np\backslash s)/s)\backslash s)\]

Determining the semantic type

We can now use this syntactic category to determine a semantic type. If we work our way down from the top, keeping the directions of the slashes in mind, we can translate this tree into the following semantic type (using tree notation):

      ─>
     / \
    ─>  t
   / \
  t  ─>
    / \
   e   t

Or in parentheses notation: \[((t → (e → t)) → t)\] This is the type of a function that consumes one argument and returns a truth value. The argument of this function must itself be a function that takes two arguments in order—a truth value, followed by an entity—and then returns a truth value.

## First example

This expression takes a sentence to its right, and then a sentence to its left, to form a sentence.

### Determining the syntactic category

Because the expression first takes a sentence to its right, we know that its syntactic category is going to look as follows:
$$(\ldots / s)$$
That is, we know that this category's main operator is a right slash ($/$) because the first thing the expression does is take something to its right;
and we know that the category appearing to the *right* of this right slash is $s$ because the thing the expression takes to its right is a *sentence*.
In tree notation, the category would look as follows (where the ellipsis ('$\ldots$') represents the rest of the category, which is still TBD):
```
  (/)
  / \
...  s
```

After the expression takes the sentence to its right, it takes another sentence to its left.
Knowing this, we can begin to say something about what's missing (the '$\ldots$').
In particular, what we want to substitute in for the missing part is a syntactic category for an expression that takes a *sentence* to its left.
In general, such a category looks as follows:
$$(s\backslash \ldots)$$
Or in tree notation:
```
  (\)
  / \
 s  ...
```
If we want, we can now substitute this result in for what was missing in the syntactic category above.
If we do this, we get the following (partial) category:
$$((s\backslash \ldots)/s)$$
Or in tree notation:
```
   (/)
   / \
 (\)  s
 / \
s  ...
```
Finally, when the expression has taken a sentence to its right and then a sentence to its left, it produces a sentence.
Thus we know how to finish the tree:
just stick an $s$ in for the last missing part:
$$((s\backslash s)/s)$$
Or in tree notation:
```
   (/)
   / \
 (\)  s
 / \
s   s
```

### Determining the semantic type

Now that we have the syntactic category, we can use it to determine its corresponding semantic type.
One way to do this is by starting at the *root* of the syntactic category represented in tree notation and working our way down.
Because the root of this tree is a right slash ($/$), and because its right child is an $s$, we know that the root of the semantic type tree is going to be an arrow ($→$) and that its *left child* is going to be a $t$ (recall that the semantic type of $s$ is $t$, and that for right slashes, the arrow "points the other way"):
```
   ─>
  / \
 t  ...
```

Meanwhile, the *right child* of this semantic type tree will be the semantic type corresponding to the *left child* of the ($/$) in the syntactic category tree.
By looking at the syntactic category tree above, we can see the left child of the root ($/$) is the following tree:
```
 (\)
 / \
s   s
```
Thus we can get the relevant semantic type by converting this left slash ($\backslash$) into an arrow ($→$) whose *left child* corresponds to the syntactic category on the left, and whose *right child* corresponds to the syntactic category on the right.
Both of these syntactic categories are $s$, which means that the two children in the semantic type will both be $t$:
```
   ─>
  / \
 t   t
```
With the semantic type corresponding to $(s\backslash s)$ in hand, we can show the complete semantic type corresponding to $((s\backslash s)/s)$ by filling in what was missing above:
```
  ─>
 / \
t   ─>
   / \
  t   t
```
We now have the full semantic type, in tree notation.
If we want to represent this semantic type using the more typical parentheses notation, we would write it as:
$$(t → (t → t))$$

### What category and type are these?

In fact, this syntactic category---$((s\backslash s)/s)$---and its corresponding semantic type---$(t → (t → t))$---can be seen to be useful in our system for describing English.
Specifically, it is useful to view $((s\backslash s)/s)$ as the syntactic category of sentence-level coordinators, like *and*, and thus $(t → (t → t))$ as its semantic type.
Note that sentence-coordinator *and* appears to behave as described.

(@ex-and-s) Jo jumps and Bo runs.

In (@ex-and-s), we can view *and* as first combining with the sentence *Bo runs* (["This expression takes a sentence to its right..."](examples.html#first-example)) to form the string *and Bo runs*.
This string then combines with *Jo jumps* (["...and then a sentence to its left..."](examples.html#first-example)) to form the string *Jo jumps and Bo runs*, delivering an $s$.

If we view sentence-coordinator *and* as having syntactic category $((s\backslash s)/s)$, then we also have to regard it as having semantic type $(t → (t → t))$.
This is the semantic type of functions that first take a truth value argument, and then another truth value argument, and return a truth value.
One such function, which we can call $f_{\textit{and}}$, behaves as follows:
$$\begin{align*}
f_{\textit{and}}(a)(b) &= \true \text{ if } a = \true \text{ and } b = \true \\
    &= \false \text{ otherwise}
\end{align*}$$
Here, $a$ and $b$ represent two possible truth values---they could be either $\true$ or $\false$---which we can feed, in turn, to $f_{\textit{and}}$ as its two arguments.
When $f_{\textit{and}}$ is applied to $a$, it gives back the result $f_{\textit{and}}(a)$---this is a new function of type $(t → t)$. 
When it is then applied to $b$ (yielding $f_{\textit{and}}(a)(b)$), it returns a truth value---something of type $t$.
The truth value it returns is $\true$ if and only if its two arguments ($a$ and $b$) were $\true$;
if either of them was $\false$, $f_{\textit{and}}(a)(b)$ returns $\false$.

And $f_{\textit{and}}$ seems to be a good meaning for the English word *and*.
It makes the whole sentence that it forms true if and only if the two sentences that it coordinates are true.
For example, it allows us to ensure that (@ex-and-s) is evaluated to be true if and only if both the sentences *Jo jumps* and *Bo runs* are evaluated to be true;
if either of these sentences comes out false, then so does (@ex-and-s) as a whole.
The following derivation, which assumes meanings for *runs* and *jumps* that follow the model in [An English model and example](../models/english_examples.html), shows this:
$$\begin{prooftree}
\AxiomC{$⟨\textit{Jo}, \ct{j}⟩ ⊢ np$}
\AxiomC{$⟨\textit{jumps}, \{\ct{j}\}_{CF}⟩ ⊢ (np\backslash s)$}
\RightLabel{$\backslash$}\BinaryInfC{$⟨\textit{Jo jumps}, \{\ct{j}\}_{CF}(\ct{j})⟩ ⊢ s$}
\AxiomC{$⟨\textit{and}, f_{\textit{and}}⟩ ⊢ ((s\backslash s)/s)$}
\AxiomC{$⟨\textit{Bo}, \ct{b}⟩ ⊢ np$}
\AxiomC{$⟨\textit{runs}, \{\ct{j}, \ct{b}\}_{CF}⟩ ⊢ (np\backslash s)$}
\RightLabel{$\backslash$}\BinaryInfC{$⟨\textit{Bo runs}, \{\ct{j}, \ct{b}\}_{CF}(\ct{b})⟩ ⊢ s$}
\RightLabel{$/$}\BinaryInfC{$⟨\textit{and Bo runs}, f_{\textit{and}}(\{\ct{j}, \ct{b}\}_{CF}(\ct{b}))⟩ ⊢ (s\backslash s)$}
\RightLabel{$\backslash$}\BinaryInfC{$⟨\textit{Jo jumps and Bo runs}, f_{\textit{and}}(\{\ct{j}, \ct{b}\}_{CF}(\ct{b}))(\{\ct{j}\}_{CF}(\ct{j}))⟩ ⊢ s$}
\end{prooftree}$$

#### Evaluating the result

The interpretation that results from this derivation is the following:
$$f_{\textit{and}}(\{\ct{j}, \ct{b}\}_{CF}(\ct{b}))(\{\ct{j}\}_{CF}(\ct{j}))$$
Note that this result consists of the function $f_{\textit{and}}$ applied to two arguments.
The first argument is 
$$\{\ct{j}, \ct{b}\}_{CF}(\ct{b})$$
and the second argument is 
$$\{\ct{j}\}_{CF}(\ct{j})$$
Since $\{\ct{j}, \ct{b}\}_{CF}(\ct{b}) = \true$ and $\{\ct{j}\}_{CF}(\ct{j}) = \true$ (both are *true*), we can evaluate the whole result to the following:
$$f_{\textit{and}}(\true)(\true)$$
If we consult the definition of $f_{\textit{and}}$ that used arbitrary truth values $a$ and $b$, we can see that our $a$ and $b$ here are both $\true$.
Thus $f_{\textit{and}}(\true)(\true) = \true$, which means that the interpretation of (@ex-and-s) is $\true$.

## Second example

This expression combines with an expression $X$ to its left, where $X$ is something that takes a sentence to its right to form a verb phrase, and together with $X$, it forms a sentence.

$$(\ldots \backslash s)$$

```
  (\)
  / \
...  s
```

$$((np\backslash s)/s)$$
